# Family Routine

Семейное пространство для рутины, расписаний и общих финансов.

- `backend/` — API на Rust (Axum + sqlx + PostgreSQL)
- `shared-schema/` — DTO, общие для API
- `frontend/` — клиент на Flutter (web, Android, iOS, desktop)
- `deploy/` — конфигурация внешнего TLS-прокси (Caddy)
- `.github/workflows/android-release.yml` — сборка подписанного APK
- `docs/SECURITY.md` — модель безопасности и эксплуатация секретов

## Быстрый запуск (Docker)

1. Скопируйте `.env.example` в `.env` и заполните значения:

   | Переменная | Как получить |
   |---|---|
   | `DB_PASSWORD` | `openssl rand -hex 24` (только `[0-9a-f]`, чтобы не экранировать в URL) |
   | `DATA_ENC_KEY` | `openssl rand -base64 32` — ключ шифрования банковских токенов |
   | `PASSWORD_PEPPER` | `openssl rand -base64 32` — секрет для хешей паролей |
   | `APP_DOMAIN` | домен, указывающий на сервер; `localhost` для локальной проверки |
   | `ENABLE_BANKING_APP_ID`, `ENABLE_BANKING_KEY_FILE` | необязательно, только для AIB и других банков через Enable Banking — см. «Банки» |
   | `ANTHROPIC_API_KEY` / `OPENAI_API_KEY` / `GEMINI_API_KEY` | необязательно, общий ключ сервера для распознавания чеков по фото; без него пользователи могут добавить собственные ключи в настройках — см. «Распознавание чеков» |
   | `ANDROID_CERT_SHA256` | необязательно, отпечаток ключа подписи Android-приложения для App Links — см. «Android-приложение» |
   | `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT` | необязательно, ключи Web Push для уведомлений в браузере: `docker compose run --rm --no-deps backend /app/server gen-vapid` печатает пару ключей; `VAPID_SUBJECT` — `mailto:` администратора — см. «Уведомления» |

2. `docker compose up -d --build`
3. Откройте `https://<APP_DOMAIN>`. Для публичного домена Caddy сам получит сертификат Let's Encrypt; для `localhost` используется локальный сертификат Caddy.

Наружу публикуются только порты 80/443 прокси. PostgreSQL находится во внутренней сети без доступа извне, бэкенд доступен только через nginx фронтенда.

### Сервер на Oracle Cloud (ARM)

Образы собираются и на ARM-серверах (Ampere A1 в Oracle Cloud Always Free), и на x86: Flutter для сборки веб-версии ставится из git, поэтому подходит любая архитектура. Первая сборка на 1 OCPU занимает около получаса, дальше Docker берёт неизменившиеся слои из кэша.

- Откройте TCP 80 и 443 в Security List подсети и в iptables сервера (правила ACCEPT должны стоять выше REJECT из образа Ubuntu).
- Сертификат Let's Encrypt получает сам Caddy, certbot не нужен. Если certbot уже установлен, отключите его таймер (`sudo systemctl disable --now certbot.timer`): Caddy занимает порт 80, и продление certbot всё равно будет падать.
- Ключи генерируйте именно в base64: `openssl rand -base64 32` для `DATA_ENC_KEY` и `PASSWORD_PEPPER`. С ключом в hex (`openssl rand -hex 32`) бэкенд не запустится.
- Если домен на DuckDNS, IP обновляется запросом по cron. Токен DuckDNS — секрет: с ним можно перенаправить домен на чужой сервер и получить на него сертификат.

> `DATA_ENC_KEY` и `PASSWORD_PEPPER` храните отдельно от резервных копий БД. Потеря `DATA_ENC_KEY` делает сохранённые банковские токены нечитаемыми, потеря `PASSWORD_PEPPER` — делает невозможным вход для всех пользователей. Подробнее — в `docs/SECURITY.md`.

## Разработка

### Бэкенд

При старте бэкенд сам читает `.env` из текущей папки или ближайшей родительской, поэтому `cargo run` работает и из корня, и из `backend/`. Переменные, уже заданные в окружении, важнее значений из файла. Для локального запуска в корневом `.env` нужны строки:

```dotenv
DATABASE_URL=postgres://family_routine:<пароль>@localhost:5432/family_routine
DATA_ENC_KEY=<вывод openssl rand -base64 32>
PASSWORD_PEPPER=<вывод openssl rand -base64 32>
COOKIE_SECURE=false
SQLX_OFFLINE=true
```

- `DB_USER`, `DB_PASSWORD` и `DB_NAME` читает только Docker Compose: из них он собирает `DATABASE_URL` для контейнера. `cargo run` их не использует, ему нужна готовая строка `DATABASE_URL`.
- `DATA_ENC_KEY` и `PASSWORD_PEPPER` создаются один раз. Если их сменить, пароли перестанут подходить (вход отвечает `401`), а сохранённые банковские токены — расшифровываться.
- `SQLX_OFFLINE=true` — компилятор проверяет SQL-запросы по файлам `.sqlx`, а не по живой базе, поэтому проект собирается даже со старой схемой. Схему обновят миграции при запуске сервера.
- В `docker-compose.yml` PostgreSQL наружу не открыт. Для разработки нужен отдельный экземпляр, например:

  ```bash
  docker run -d --name fr-dev-db -p 5432:5432 -e POSTGRES_USER=family_routine -e POSTGRES_PASSWORD=<пароль> -e POSTGRES_DB=family_routine postgres:16-alpine
  ```

```bash
cargo run -p backend
```

`GET /` и `GET /health` отвечают текстом — по ним удобно проверить, что сервер жив. `GET /.well-known/assetlinks.json` отдаёт Digital Asset Links для Android App Links. Остальные адреса вне `/api` возвращают `{"code":"NOT_FOUND"}`: это штатный ответ API, а не ошибка запуска.

Миграции применяются автоматически при старте. Существующая база, созданная вручную из `01_init_schema.sql`, подхватывается без пересоздания.

### Фронтенд

```bash
cd frontend
flutter pub get
flutter run -d web-server
flutter analyze
flutter test
```

- Версия Flutter — 3.47.7, как `FLUTTER_VERSION` в `frontend/Dockerfile`. От неё зависит `pubspec.lock`: Flutter фиксирует версии части пакетов (например, `intl`), поэтому на другой версии `flutter pub get` переписывает lock-файл. При обновлении Flutter закоммитьте новый `pubspec.lock` и поменяйте `FLUTTER_VERSION`.
- `web_dev_config.yaml` поднимает dev-сервер на порту 5173 и проксирует `/api/` на бэкенд `localhost:3000`. Клиент и API работают с одного origin, поэтому cookie-сессия работает без CORS и без `ALLOWED_ORIGINS`. В Codespaces достаточно открыть только порт 5173.
- `flutter run` — отладочный режим: приложение собирается из сотен отдельных модулей (DDC), и через туннель Codespaces первая загрузка может занимать минуты. Скорость так оценивать нельзя — для этого нужна release-сборка. Если в Codespaces не проходит WebSocket отладчика (`$dwdsSseHandler … failed`, затем `Library not defined`), отладочная сборка не запустится — используйте release-сборку ниже.
- Release-сборка локально и в Codespaces, так же как в продакшене за nginx:

  ```bash
  cd frontend
  flutter build web --release --wasm --csp --no-web-resources-cdn
  python3 tool/serve_web.py
  ```

  Сервер слушает порт 5173, отдаёт `index.html` для путей приложения (`/app/...`, `/auth`), проксирует `/api/` на `http://localhost:3000` (`--api` меняет адрес) и ставит те же заголовки безопасности и CSP, что `nginx.conf`. Сборку с движком Flutter из CDN (без `--no-web-resources-cdn`) он отклоняет: продакшен-CSP её блокирует. Простой `python3 -m http.server` не подходит — он не проксирует `/api` и не знает про пути приложения. После изменений кода повторите `flutter build web` и обновите страницу.
- В web-сборке сессия хранится в HttpOnly-cookie (недоступна JavaScript), на мобильных и desktop — токен в защищённом хранилище ОС (Keychain / Keystore).
- Без `API_URL` web-клиент обращается к тому же origin, с которого загружен (`/api` проксирует nginx или dev-сервер).
- `web/flutter_bootstrap.js` запускает приложение без устаревшего service worker Flutter (`flutter_service_worker.js` не регистрируется): на корневом scope работает только `web/push_sw.js`, который показывает push-уведомления и не кэширует файлы приложения.
- Продакшен-сборка: `flutter build web --release --wasm --csp --no-web-resources-cdn`. Браузеры с WasmGC (Chrome/Edge 119+, Firefox 120+, Safari 18.2+) получают WebAssembly, остальные — JS. Сборка обходится без динамической генерации кода и внешних CDN, что позволяет строгую Content-Security-Policy.
- Release-сборка через nginx (предсжатые gzip-файлы, ревалидация по ETag) показывает первый кадр примерно за 0,3 с в локальной сети, около 1,5 с при первом заходе на канале 20 Мбит/с и около 0,4 с при повторном.
- Сканер штрихкодов в браузере использует встроенный `BarcodeDetector` (Chrome на Android, macOS), а где его нет (iOS Safari, Firefox, Chrome на Windows и Linux) — библиотеку [zxing-wasm](https://github.com/Sec-ant/zxing-wasm) (MIT). Она лежит в `web/vendor/zxing-wasm` и загружается с того же origin, поэтому CSP не открывает внешние CDN. Обновление: `tool/fetch_zxing_wasm.sh <версия>` — скрипт скачивает пакет из npm и сверяет SHA-256 wasm-файла с контрольной суммой из самого пакета.
- Камера в браузере работает только по HTTPS или на `localhost`.
- Иконки Lucide подключены собственным шрифтом (`assets/fonts/lucide.ttf`, лицензия ISC) через класс `AppIcons`. В release-сборке шрифт урезается до использованных глифов (~13 КБ). Новая иконка добавляется в `lib/ui/common/app_icons.dart` с кодом глифа из [lucide.dev](https://lucide.dev).

## Android-приложение

Приложение для Android — тот же клиент Flutter: `com.familyroutine.family_routine`, название «Family Routine», Android 7.0+ (minSdk 24, его требуют плагины хранилища токенов и браузера), targetSdk и compileSdk 36. Сборка — Flutter 3.47.7, Android Gradle Plugin 9.1.0, Gradle 9.3.1, Kotlin 2.4.0, Java 17, как в шаблоне этой версии Flutter: на более старых AGP 8.11, Gradle 8.14 и Kotlin 2.2 Flutter 3.47 уже выдаёт предупреждения, а следующая версия их не примет. Все нативные плагины (`flutter_secure_storage`, `mobile_scanner`, `image_picker`, `url_launcher`, `shared_preferences`, `flutter_timezone`, `flutter_local_notifications`) собираются с этими версиями: им нужен compileSdk не выше 36 и minSdk не выше 24.

- **Разрешения:** интернет, камера (сканер штрихкодов и фото чеков), уведомления (Android 13+, запрашиваются кнопкой в настройках) и запуск после перезагрузки (чтобы восстановить запланированные напоминания). Камера не обязательна для установки: на устройстве без неё эти функции недоступны. Для уведомлений по расписанию включено core library desugaring (`desugar_jdk_libs`), его требует плагин `flutter_local_notifications`; точные будильники не используются, поэтому отдельное разрешение на них не нужно.
- **Резервное копирование выключено** (`allowBackup="false"`, правила `data_extraction_rules.xml` исключают все данные): токен сессии зашифрован ключом Android Keystore, который не переносится на другое устройство, и восстановленная копия не расшифровалась бы. После переноса на новый телефон нужно войти заново.
- **Иконка** — домик Lucide на фирменном синем (`#1F5FD6`), адаптивная (с монохромным вариантом для тематических иконок Android 13+); те же иконки у веб-версии.

### Сборка в GitHub Actions

Workflow `.github/workflows/android-release.yml` собирает release-APK, подписывает его ключом из секретов репозитория и проверяет подпись (отладочным ключом подписанный APK не публикуется).

- **Вручную:** Actions → Android release → Run workflow. Поле `api_url` — адрес сервера, к которому обращается приложение (по умолчанию `https://familyroutine.duckdns.org`). Только `https://` и домен, без пути.
- **Проверка сборки без ключа:** тот же запуск с галочкой `check_only` собирает APK без секретов подписи и ничего не публикует — так можно убедиться, что проект собирается, ещё до создания ключа.
- **По тегу:** `git tag v1.2.0 && git push origin v1.2.0` — сборка с адресом по умолчанию, APK и его SHA-256 публикуются в GitHub Release этого тега.
- APK любого запуска лежит 30 дней в Artifacts (`family-routine-apk`). Имя файла — `family-routine-<версия>-<номер запуска>.apk`.
- Версия (`versionName`) — из тега (`v1.2.0` → `1.2.0`) или из `pubspec.yaml`, номер сборки (`versionCode`) — номер запуска workflow. Он только растёт, поэтому новый APK ставится поверх старого.
- В сводке запуска (Summary) выводится SHA-256 сертификата подписи — его нужно указать в `ANDROID_CERT_SHA256` на сервере.

#### Ключ подписи и секреты

Ключ создаётся один раз (нужен JDK с `keytool`):

```bash
keytool -genkeypair -v -keystore upload-keystore.jks -storetype PKCS12 \
  -keyalg RSA -keysize 4096 -validity 10000 -alias upload
base64 -w0 upload-keystore.jks > upload-keystore.jks.b64
```

На macOS вторая команда — `base64 -i upload-keystore.jks -o upload-keystore.jks.b64`. Пароль хранилища придумайте из букв и цифр (например, `openssl rand -hex 16`): он записывается в `key.properties`, где обратная косая черта и пробелы по краям меняют значение. В формате PKCS12 пароль ключа совпадает с паролем хранилища.

В репозитории: Settings → Secrets and variables → Actions → New repository secret:

| Секрет | Значение |
|---|---|
| `ANDROID_KEYSTORE_BASE64` | содержимое `upload-keystore.jks.b64` |
| `ANDROID_KEYSTORE_PASSWORD` | пароль хранилища |
| `ANDROID_KEY_ALIAS` | `upload` (значение `-alias`) |
| `ANDROID_KEY_PASSWORD` | пароль ключа; для PKCS12 — тот же пароль хранилища |

Если какого-то секрета нет, workflow останавливается до сборки и перечисляет недостающие. Сам `upload-keystore.jks` храните вне репозитория (`*.jks` и `key.properties` в `.gitignore`) и в резервной копии: без того же ключа новую версию нельзя установить поверх старой, а App Links придётся перенастраивать. Файлы `.b64` после добавления секрета удалите. В workflow ключ расшифровывается только на время сборки и удаляется в конце, даже если сборка упала.

### App Links: возврат из банка в приложение

Ссылки `https://<домен>/app/...` открываются в приложении, если Android подтвердил, что домен разрешает это приложению. Так работает возврат из банка: страница Enable Banking (AIB) открывается во внешнем браузере, после подтверждения банк перенаправляет на `https://<домен>/app/bank-callback?code=…&state=…`, и Android открывает этот адрес сразу в приложении, где завершается подключение. Домен App Links — хост из `api_url` сборки, поэтому `ENABLE_BANKING_REDIRECT_URL` должен указывать на тот же домен.

1. Возьмите SHA-256 сертификата из сводки запуска workflow или из ключа: `keytool -list -v -keystore upload-keystore.jks -alias upload | grep SHA256`.
2. В `.env` сервера укажите `ANDROID_CERT_SHA256=<отпечаток>` (несколько — через запятую, например ключ загрузки и ключ Google Play App Signing). `ANDROID_PACKAGE_NAME` менять не нужно. Примените: `docker compose up -d`.
3. Проверьте, что файл отдаётся: `curl -i https://<домен>/.well-known/assetlinks.json` — ответ `200`, `Content-Type: application/json`, без перенаправлений. Caddy передаёт запрос в nginx, nginx — бэкенду. Проверка Google: `https://digitalassetlinks.googleapis.com/v1/statements:list?source.web.site=https://<домен>&relation=delegate_permission/common.handle_all_urls`.
4. Android проверяет домен при установке приложения. Если `ANDROID_CERT_SHA256` задан позже, переустановите приложение или выполните `adb shell pm verify-app-links --re-verify com.familyroutine.family_routine`; состояние — `adb shell pm get-app-links com.familyroutine.family_routine` (должно быть `verified`).

Пока домен не подтверждён, ссылка открывается в браузере — в веб-версии, где подключение банка завершится только если там выполнен вход.

### Локальная сборка

Нужны Android SDK (platform 36) и JDK 17.

```bash
cd frontend
flutter build apk --release --dart-define=API_URL=https://familyroutine.duckdns.org -P appLinkHost=familyroutine.duckdns.org
```

Без `API_URL` приложение обращается к `http://127.0.0.1:3000` — это адрес для desktop-отладки; для телефона всегда указывайте `API_URL` с `https://`, Android блокирует незашифрованный HTTP. Для подписи своим ключом создайте `frontend/android/key.properties`:

```properties
storeFile=upload-keystore.jks
storePassword=<пароль>
keyAlias=upload
keyPassword=<пароль>
```

и положите ключ в `frontend/android/app/upload-keystore.jks`. Без `key.properties` release-сборка подписывается отладочным ключом: она годится для проверки, но App Links для неё не подтвердятся.

## Банки

Подключение — «Кошельки → Подключить банк». Каждое подключение создаёт кошельки для счетов банка, дальше операции и баланс загружаются в фоне.

### Monobank

Пользователь вставляет личный токен с [api.monobank.ua](https://api.monobank.ua). Токен даёт только чтение выписки, сервер хранит его зашифрованным. Опрос — раз в `MONOBANK_POLL_INTERVAL_MIN` минут. При первом подключении загружается история за `MONOBANK_HISTORY_MONTHS` месяцев. API отдаёт не больше 31 дня за запрос и 1 запрос в минуту, поэтому два года истории подтягиваются примерно за полчаса — операции появляются постепенно.

### AIB через Enable Banking

1. Зарегистрируйте приложение в панели [Enable Banking](https://enablebanking.com/cp/applications). Панель выдаёт приватный ключ `<id приложения>.pem` — имя файла и есть `ENABLE_BANKING_APP_ID`.
2. В настройках приложения добавьте адрес возврата `https://<APP_DOMAIN>/app/bank-callback`.
3. Положите ключ в `secrets/enable_banking.pem` (папка в `.gitignore`), выполните `chmod 700 secrets` и `chmod 644 secrets/enable_banking.pem` (ключ читает пользователь контейнера с другим UID). В `.env` укажите:

   ```dotenv
   ENABLE_BANKING_APP_ID=<id приложения>
   ENABLE_BANKING_KEY_FILE=./secrets/enable_banking.pem
   ```

   Docker Compose монтирует ключ в контейнер только для чтения. `cargo run` читает тот же `.env`, относительный путь считается от папки с `.env`, поэтому запуск работает и из корня, и из `backend/`. Если приложение открыто не на `APP_DOMAIN` (например, dev-сервер Flutter в Codespaces), задайте `ENABLE_BANKING_REDIRECT_URL=https://<адрес клиента>/app/bank-callback` и зарегистрируйте этот адрес в Enable Banking.
4. Ключ никогда не коммитьте и не кладите в образ. Если он мог утечь, создайте новый в панели Enable Banking.

При старте бэкенд запрашивает у Enable Banking данные приложения и пишет в журнал окружение, признак активности и предупреждение, если `ENABLE_BANKING_REDIRECT_URL` нет среди зарегистрированных адресов. Адрес возврата может заканчиваться на `/app/bank-callback` или `/bank/callback`, оба пути ведут на один экран.

Если подключение не проходит, бэкенд пишет в журнал ответ Enable Banking (строка `enable banking <код> on <путь>: …`), а приложение показывает причину:

- «Enable Banking отклонил запрос» (`BANK_REJECTED`) — чаще всего адрес возврата из `ENABLE_BANKING_REDIRECT_URL` не зарегистрирован в панели Enable Banking. Адрес должен совпадать посимвольно.
- «Приложение в Enable Banking не активно» (`BANK_APP_INACTIVE`) — пока приложение в статусе Inactive, Enable Banking отклоняет все запросы API, поэтому активировать его из нашего приложения нельзя. Production-приложение без договора активируется в панели кнопкой «Activate by linking accounts»: после привязки своих счетов оно работает, но только с этими счетами.
- «Enable Banking не принял ключ приложения» (`BANK_APP_REJECTED`) — `ENABLE_BANKING_APP_ID` не совпадает с ключом.
- Пустой список банков в диалоге подключения — приложение работает в sandbox, где доступны только тестовые банки.

Пользователь выбирает банк, подтверждает доступ на сайте банка и возвращается в приложение. Первая синхронизация запрашивает всю историю, которую отдаёт банк, дальше опрос идёт в часы `ENABLE_BANKING_SYNC_HOURS`: PSD2 разрешает 4 фоновых запроса в сутки. Согласие действует `ENABLE_BANKING_CONSENT_DAYS` дней, после этого банк нужно подключить заново.

Кнопка «Обновить» у подключения запускает синхронизацию вручную: не чаще раза в 2 минуты для Monobank и раза в 2 часа для Enable Banking.

## Финансы

- Вкладка «Финансы». Справа вверху закреплена кнопка фильтров, слева от неё — выбранные значения: кошельки (все, только мои, кошельки участника, один кошелёк), период (7 или 30 дней, этот месяц, 90 дней или любой диапазон в календаре), пересчёт в одну валюту и учёт переводов. Фильтр действует на операции, «Доходы и расходы» и категории.
- Блоки сверху вниз: подключённые банки, карты и кошельки, чеки, последние операции, «Доходы и расходы», категории. В каждом блоке до 5 записей; «+» слева добавляет (банк, кошелёк, чек, наличные), стрелка справа открывает полный список.
- «Доходы и расходы» на телефоне показывают 7 столбцов фиксированной ширины; лента прокручивается пальцем, открывается на последних днях, выбранный столбец описан над графиком (на компьютере — при наведении, на телефоне — долгим нажатием). На широком экране весь период помещается сразу. Кнопка «Таблица» показывает те же цифры списком.
- **Переход к операциям.** Нажатие на столбец (или строку таблицы) открывает список операций за этот день, неделю или месяц — с теми же кошельками, что выбраны в фильтре, по дате, новые сверху.
- **Настройки графика** — шестерёнка справа в заголовке блока: группировка по дням, неделям (с понедельника) или месяцам и вид графика. «Приходы и расходы» — столбцы вверх и вниз за каждый период; «Накопительный баланс» — линия от нуля в начале выбранного периода: каждый приход поднимает её, каждый расход опускает, над графиком показан баланс на выбранную дату. Выбор запоминается на устройстве. При пересчёте валют курс берётся на день каждой операции, даже если группировка по неделям или месяцам.
- Категории: кольцевая диаграмма и список с долями. На телефоне это две вкладки «Список» и «Диаграмма», переключаются нажатием или свайпом внутри блока. Нажатие на категорию открывает её операции за выбранный период.
- «Транзакции» — операции всех доступных кошельков с поиском и фильтром: все кошельки, только мои, кошельки конкретного участника группы или один кошелёк. Банковские операции нельзя изменить или удалить, можно поменять категорию и заметку.
- **Перевод валют в списках.** Шестерёнка в блоке «Транзакции» и на экране всех операций открывает настройки списка: переключатель «Переводить в одну валюту» и выбор валюты. Каждая сумма пересчитывается по курсу НБУ на день операции и показывается крупно, исходная сумма — мелко под ней; если курса ещё нет, сумма остаётся в исходной валюте, а над списком написано, для каких валют курса не хватило. Настройка общая с фильтром вкладки «Финансы».
- **Остаток несинхронизированных кошельков.** У кошельков без подключения к банку остаток считается так: последний документ остатка плюс все операции после него. Операции с датой раньше последнего документа на текущий остаток не влияют. Пока документов нет, остаток считается с нуля от первой операции; для кошелька, который раньше синхронизировался с банком, — от последнего остатка банка. Документ («Указать остаток» в карточке кошелька) — фактическая сумма на дату и время. Первый документ — начальный остаток, у следующих показывается расхождение с учётом: прошлый документ плюс операции между ними. Расхождение можно закрыть в любой момент: «Списать расход» или «Записать доход» создают операцию с выбранной категорией внутри периода документа, а «Добавить чек» (для наличных) открывает новый чек с этим кошельком и датой документа. Такие операции попадают в статистику как обычные; само нераспределённое расхождение в графики не попадает. При удалении документа удаляются и созданные из него списания, а при переносе даты списания переносятся в новый период.
- **Личные кошельки в группе.** По умолчанию участники группы не видят ваших личных кошельков. В карточке группы блок «Мои кошельки в группе» включает показ каждого кошелька отдельно для каждой группы. Участники видят такой кошелёк, его транзакции и привязанные к ним чеки, но изменять ничего не могут; у чужих кошельков, операций и чеков подписан владелец. Чек без транзакции из открытого кошелька остаётся видимым только автору. Доступ пропадает сразу после выключения переключателя или выхода из группы.
- «Наличные» — приход в кошелёк наличных. «В наличные» — перевод между кошельками: снятие в банкомате превращается в перевод, и вторая половина появляется в кошельке наличных. Переводы не считаются доходом или расходом.
- «Чеки» — магазин, позиции (количество, цена, сумма) и привязанные транзакции. Если позиции покрывают не всю оплату, разница показывается строкой «Остальное». Если позиции дороже оплаты, разница записывается расходом из выбранного кошелька наличных.
- Позиции чека выбираются из справочника «Товары и услуги» (поиск по названию или штрихкоду по мере ввода). Новую позицию можно добавить в справочник прямо из чека. У позиции есть тип (товар, услуга, еда) и единица измерения: в ней вводится количество и сравнивается цена.
- В чеке можно указать место и его филиал: цены сравниваются по каждому филиалу отдельно.
- Скидки: акция на конкретный товар (например, «2 за 3 €» или SAVER DEAL) вычитается из суммы этих позиций, поэтому в сравнении цен видна реальная цена. Ваучер, купон или баллы на весь чек вводятся в поле «Скидка на весь чек»: цены позиций не меняются, а сумма к оплате уменьшается.
- При группировке по дням и периоде не длиннее двух суток график строится по часам.
- Режим «Без переводов» (по умолчанию) не считает доходом или расходом переводы между своими счетами, а также снятие и внесение наличных: снятые с карты и положенные обратно 100 € остаются теми же 100 €. Режим «Обороты» показывает все движения денег.
- Переводы между своими счетами находятся автоматически после каждой синхронизации. Пара связывается, только если она однозначна; уровни уверенности по убыванию: обмен валют с точной суммой во второй валюте (EUR ⇄ UAH в Monobank); одинаковая сумма и обе операции похожи на перевод; одинаковая сумма и одна из них похожа на перевод; разные валюты с расхождением по курсу НБУ не больше 3% за два дня. Разорванная вручную связь больше не восстанавливается. Неоднозначный перевод можно связать вручную: «Перевод между моими счетами» в карточке операции.
- Галочка «Пересчитать в» сводит все валюты в одну по официальному курсу НБУ на дату операции. Курсы загружаются в фоне за всю историю операций (до трёх лет); пока курса нет, интерфейс пишет, какие суммы не учтены.
- Категории: правило пользователя → MCC → описание операции (у AIB MCC нет, поэтому Tesco, Costa, банкомат, SEPA и т. п. распознаются по тексту). Если изменить категорию и отметить «Применить ко всем похожим», она назначится похожим операциям сейчас и новым при синхронизации; изменённая вручную категория больше не перезаписывается.

## Товары, магазины и цены

- **Общий справочник.** Товары и услуги видят и используют в чеках все пользователи. У каждой позиции есть подпись автора: «Вы», «Общая база» (позиции администраторов и позиции удалённых пользователей) или «Другой пользователь». Имя автора показывается только участникам общей группы: остальным по подписи нельзя связать позицию с человеком и узнать, что он покупал. Название, штрихкод и КБЖУ видны всем, поэтому личные данные в названии писать не стоит; чеки и цены остаются приватными.
- **Кто может менять.** Свою позицию автор меняет и удаляет, пока её нет в чеках и отметках цен других пользователей. Как только позиция попала в чужой чек, её название, тип, единица и штрихкод, а также уже заполненные масса нетто, вес 1 шт. и категория фиксируются, удалить и объединить её нельзя; КБЖУ автор уточнять может. Администраторы из `ADMIN_EMAILS` редактируют любые позиции, в том числе используемые, и объединяют дубликаты: чеки и цены всех пользователей переходят к выбранной позиции, а пустые штрихкод и КБЖУ дополняются из удалённой. Удалить позицию, которая есть в чьих-то чеках, не может никто — для дубликатов есть объединение.
- **Пустое дополнит любой.** Если у позиции не заполнены КБЖУ (для еды), масса нетто, вес 1 шт. или категория, их может заполнить любой вошедший пользователь, даже в чужой позиции. Сервер записывает только поля, которые были пустыми; заполненное значение меняет лишь автор (пока позицию не используют другие) или администратор.
- **Названия и штрихкоды уникальны** во всём справочнике: при попытке создать позицию с существующим названием или штрихкодом приложение предлагает взять уже имеющуюся. Штрихкод — EAN или UPC (8–14 цифр, контрольная цифра проверяется), необязателен.
- **Open Food Facts.** Кнопка «Найти в Open Food Facts» и сканирование нового штрихкода заполняют название (с брендом и объёмом), тип «Еда» и КБЖУ на 100 г из открытой базы Open Food Facts. Сервер запрашивает только нужные поля, представляется как `FamilyRoutine/1.0`, ждёт не дольше 6 секунд и хранит ответ 30 дней (ответ «не найдено» — сутки). Если товара нет или сервис недоступен, карточка заполняется вручную. В Open Food Facts уходит только штрихкод.
- **Фото этикетки.** «Заполнить по фото этикетки» читает название, бренд, объём, штрихкод и КБЖУ нейросетью — тем же ключом и с теми же лимитами, что распознавание чеков. Фото уменьшается в браузере до 1600 точек по большей стороне (JPEG 80 %), сервер принимает не больше 2 МБ и никуда его не сохраняет.
- **Сканер камерой.** Кнопка «Сканировать товары» в чеке открывает камеру телефона: каждый распознанный штрихкод добавляет позицию, повтор того же товара увеличивает количество. Пока код остаётся в кадре, он не добавляется повторно — для второй такой же покупки уберите камеру и наведите снова. Если позиции с таким кодом нет, сразу открывается её создание с уже заполненным штрихкодом и данными из Open Food Facts. Иконка сканера есть также у каждой строки чека, в форме позиции и в справочнике (найденная позиция открывается, ненайденная — создаётся). Код можно ввести и вручную, а USB/Bluetooth-сканер работает как клавиатура в поле поиска позиции.
- **Масса нетто.** В карточке товара, который продаётся штуками, есть поле «Масса/объём нетто» в граммах или миллилитрах — сколько в упаковке. По нему считается цена за 100 г или 100 мл; дальше оно понадобится для учёта запасов. Весовым товарам (кг, л) поле не нужно: масса берётся из количества в чеке. Open Food Facts и фото этикетки заполняют массу сами: `400 g`, `0,5 kg`, `1,5 l`, `33 cl`, `250 ml x 4` превращаются в граммы и миллилитры, а у мультипака вида `4 x 125 g` записывается нетто 500 г и вес одной штуки 125 г.
- **Категории товаров** — общее для всех дерево «категория → подкатегория → тип», например Молочные продукты › Сыр › Маасдам или Мясо › Свинина › Бекон. Для старта в справочнике уже есть 15 категорий и около 50 подкатегорий с названиями на всех языках приложения, типы добавляют пользователи. Категория выбирается в карточке товара: поиск по названию, раскрытие ветвей, создание новой подкатегории прямо из выбора. Экран «Категории товаров» — в кнопке справочников.
  - *Кто может менять.* Создать узел может любой. Переименовать, перенести или удалить узел может его автор, пока в его ветке нет чужих товаров и чужих подкатегорий; администраторы (`ADMIN_EMAILS`) могут всё, в том числе объединить дубликаты: товары и подкатегории переходят в выбранный узел, одноимённые подкатегории сливаются. При удалении узла его товары переходят в родительскую категорию, узел с подкатегориями удалить нельзя.
  - *Глубина* ограничена переменной `PRODUCT_CAT_MAX_DEPTH` (по умолчанию 3, от 1 до 10). Сервер не даёт перенести узел внутрь собственной ветки и проверяет, что переносимая ветка целиком помещается в лимит. Если лимит уменьшить, существующие более глубокие ветки продолжают работать — запрещается только создавать новые уровни глубже лимита.
- **Лучшая цена за 100 г / 100 мл.** На экране любого узла (категории, подкатегории или типа) — рейтинг всех товаров его ветки по цене за 100 г или 100 мл: лучшая цена с магазином, филиалом и датой, последняя цена и число покупок. Учитываются ваши чеки и отметки цен и чеки участников, которые делятся ценами. Фильтры: период (30 и 90 дней, год, всё время), валюта пересчёта по курсу НБУ на дату покупки и магазин. Товары без массы нетто показаны отдельно — по ним цену за 100 г не посчитать, нажатие открывает карточку, чтобы заполнить массу.
- **Места** хранятся либо только у вас, либо в группе — тогда их видят и используют в чеках все участники. Новые места по умолчанию сохраняются в вашей первой группе, выбор можно поменять при создании. Личное место можно перенести в группу (обратно — нельзя). Изменять место группы может его автор или администратор группы.
- **Филиалы.** У места может быть несколько адресов; один из них основной. Для адреса достаточно страны и города, улица, дом и индекс — по желанию. Место можно сохранить и вовсе без адреса.
- **Место у банковской операции.** Банки называют один и тот же магазин по-разному: Monobank пишет «Lidl», AIB — «VDC-LIDL 0907 ATHL; Purchase». В карточке операции видно название продавца в банке и кнопка «Указать место»: можно выбрать существующее место и филиал или создать новое. Привязка действует на все прошлые и будущие операции с этим названием, а разные названия одного магазина привязываются к одному месту. Приложение подсказывает место по совпадению слов («LIDL» → «Lidl») и филиал по городу («ATHL» → «Athlone»). После привязки операция в списке называется именем места, а поиск по нему находит операции из всех банков.
- Привязки личные: они видны только вам, даже если само место общее для группы. Список названий в банке и кнопка «Отвязать» есть в карточке места. Если чек с местом связан с банковской операцией, место для её продавца запоминается автоматически.
- **Актуальная цена и история.** Карточка позиции показывает последнюю цену за единицу с валютой, датой и магазином (и филиалом, если он указан), а ниже — историю цен. Порядок определяется датой покупки в чеке, а не временем ввода, поэтому чек, внесённый задним числом, не вытесняет более свежую цену. При выборе позиции в чеке пустое поле цены заполняется последней ценой в валюте чека, причём покупка в том же магазине важнее более свежей покупки в другом.
- **«Где выгоднее».** Карточка позиции показывает цену за единицу в каждом магазине и филиале: последнюю, минимальную и среднюю, и отмечает самую низкую. Учитываются ваши чеки и отметки «Отметить цену» — цена, увиденная в магазине без покупки (можно указать цену за упаковку и её объём, например 0,9 л). Галочка «Пересчитать в» сводит все валюты в одну по курсу НБУ на дату покупки.
- **Цены группы.** Цены из чеков других участников группы учитываются автоматически. Видны магазин, цена и дата, но не суммы чеков и другие покупки. После выхода из группы цены участника перестают учитываться.
- При удалении группы её места переходят к авторам, если те ещё в группе, иначе — владельцу.

## Распознавание чеков

Кнопка «Распознать чек» в новом или уже сохранённом чеке: сфотографируйте бумажный чек или выберите фото — нейросеть прочитает магазин, адрес, дату, валюту и позиции и заполнит чек. Ничего не сохраняется, пока вы не нажмёте «Сохранить», поэтому распознанное можно проверить и поправить.

- **Позиции.** Строка чека сопоставляется с общим справочником: по штрихкоду, по тексту строки, который вы уже связывали с позицией в прошлых чеках, по точному названию и по похожему названию с той же единицей (такие строки помечаются «Похоже на …»). Не найденные позиции помечаются как новые и создаются в справочнике при сохранении. Если поменять позицию в строке, при следующем распознавании этот текст чека будет связан с выбранной позицией.
- **Уже введённые позиции.** Если в чеке уже есть строки (отсканированные штрихкоды, набранные вручную, сохранённый чек или прошлое распознавание), распознавание не добавляет их второй раз, а дополняет. Нейросеть получает только их названия, штрихкоды и единицы — без цен и количеств, чтобы читать чек независимо, — и для каждой строки чека указывает, какой введённой позиции она соответствует, даже если название в чеке сокращено («МОЛ ПРОСТ 2.5% 0.93Л» и «Молоко Простоквашино 2,5% 930 мл»). Сервер сначала связывает строки сам — по той же позиции справочника, штрихкоду или точному названию — и только потом берёт ответ нейросети. Дальше:
  - у найденной строки остаётся выбранная позиция, а количество, цена и сумма берутся из чека; если они изменились, под строкой видно «Обновлено по чеку, было: 2 шт на 90,00 ₴»;
  - одна позиция, пробитая в чеке несколькими строками, складывается в одну строку;
  - введённая позиция, которой нет в чеке, остаётся и помечается «Нет в распознанном чеке — проверьте или удалите»;
  - остальные строки чека добавляются, как обычно.
  При сохранении текст строки чека запоминается для найденной позиции, поэтому в следующий раз она найдётся по нему сразу, без подсказок нейросети.
- **Место.** Магазин ищется среди ваших мест и мест ваших групп по названию, филиал — по номеру дома и улице. Если магазина нет, он создаётся при сохранении из данных чека (название, страна, город, улица, дом, индекс, если он есть); если магазин есть, а адрес новый — добавляется филиал.
- **Сумма.** Скидки учитываются в цене позиции. Если сумма позиций не совпадает с итогом чека, это видно до сохранения.

### Провайдеры и собственные ключи

Поддерживаются Anthropic (Claude), OpenAI (ChatGPT) и Google (Gemini). В «Настройки → Распознавание чеков» пользователь выбирает, чем распознавать:

- **Ключ сервера** — если администратор задал его в окружении. Действуют лимиты сервера `RECEIPT_AI_DAILY_LIMIT` и `RECEIPT_AI_MONTHLY_LIMIT`; пользователь может только уменьшить их для себя.
- **Свой ключ API** любого из трёх провайдеров. При сохранении сервер проверяет ключ, запрашивая у провайдера список моделей, и предлагает модель по умолчанию (Claude Opus 5.5; у OpenAI — самая новая основная модель GPT; у Gemini — стабильная Pro, иначе стабильная Flash). Модель можно сменить на любую из списка. Расходы оплачивает владелец ключа, лимиты (по умолчанию 30 чеков в день и 300 в месяц, максимум 1000 и 30 000) он задаёт сам; в настройках видно, сколько чеков и токенов израсходовано за день и месяц.
- Нужен именно ключ API: подписки Claude Pro и ChatGPT Plus доступа к API не дают. Ключи: [console.anthropic.com](https://console.anthropic.com/settings/keys), [platform.openai.com](https://platform.openai.com/api-keys), [aistudio.google.com](https://aistudio.google.com/apikey).
- Названия моделей у провайдеров меняются часто, поэтому список моделей приложение берёт у провайдера по ключу пользователя, а не хранит в коде. Из списка скрыты модели, не подходящие для чтения фото (речь, эмбеддинги, генерация изображений и т. п.) и устаревшие поколения.
- **Стоимость** зависит от модели: крупные модели (Claude Opus, GPT, Gemini Pro) стоят несколько центов за чек, младшие (Claude Haiku, GPT mini, Gemini Flash) — в десятки раз дешевле; качество на мятых и длинных чеках проверьте сами.
- **Конфиденциальность.** Перед первым распознаванием через каждого провайдера приложение предупреждает, что фото уйдёт к нему. Фото не сохраняется ни в базе, ни в логах сервера — только распознанный текст, если вы сохраните чек. Запросы к OpenAI отправляются с `store: false`. У бесплатного ключа Gemini Google может использовать запросы для улучшения своих продуктов, с включённой оплатой — нет.
- Для Claude поколения 5 (кроме Haiku) включён серверный fallback (`fallbacks: "default"`): если фильтры безопасности модели отклонят запрос, API повторит его на рекомендованной Anthropic резервной модели.

## Профиль и замеры

«Мой профиль» в меню (или имя в шапке меню): личные данные, замеры, кто их видит, смена пароля.

- **Личные данные:** имя, фамилия, дата рождения, пол и повседневная активность без учёта тренировок. Пол и активность понадобятся для расчёта обмена веществ и норм питания. Email пока не меняется.
- **Замеры.** Замер — это дата и время плюс любые показатели:
  - рост и вес;
  - состав тела: жир, мышечная и скелетная мышечная масса, костная масса, вода, белок, висцеральный жир;
  - обхваты: шея, грудь, талия, бёдра, бицепсы, предплечья, бёдра и голени слева и справа.

  Заполняется только то, что измерили. Значения проверяются по допустимым диапазонам, например вес 1–350 кг.
- **Текущие значения и история.** На профиле — последние значения и изменение с прошлого замера. По нажатию — история показателя: график, сводка (сейчас, изменение за период, минимум и максимум) и список замеров с правкой и удалением. Для веса показан сглаженный тренд: он убирает суточные колебания из-за воды и еды.
- **Кто видит.** Участники ваших групп видят все ваши показатели («Рост и вес», «Состав тела», «Обхваты»), возраст и пол — отдельных переключателей нет. Сначала видны текущие значения, по нажатию — история. Дата рождения, email и уровень активности другим не показываются.
- **Смена пароля** требует текущий пароль и выводит из аккаунта все остальные устройства.

### Детские профили

Администратор группы может добавить ребёнка без своего аккаунта: «Группа → Добавить ребёнка», указать имя, фамилию, дату рождения и пол.

- Данные ребёнка — замеры, распорядок, питание, норму, тренировки и события плана — вносят создатель профиля, владелец и администраторы групп, в которых состоит ребёнок. Остальные участники видят их так же, как данные взрослых, но изменить не могут.
- Ребёнок показывается в распорядке группы наравне со всеми. Нажатие на его имя на шкале суток открывает выбор статуса, а в блоках «Питание сегодня», «Тренировки», «План на сегодня» его можно выбрать свайпом и добавлять записи кнопкой «+».
- Еда ребёнка списывается со склада по умолчанию того, кто её записал. Напоминания и уведомления детскому профилю не приходят.
- Войти в детский профиль нельзя. Его нельзя сделать администратором или владельцем.
- Если убрать ребёнка из последней его группы (или удалить группу), профиль и все его замеры удаляются.

## Тренировки

«Тренировки» в меню: программы, план на ближайшие дни, проведённые тренировки.

- **Программа** — несколько дней (A, B, C…), в каждом упражнения из справочника: подходы, диапазон повторов, вес или время, отдых между подходами, шаг прибавки веса. В справочнике 43 стандартных упражнения (базовые со штангой и гантелями, тренажёры, упражнения с весом тела, кардио, растяжка), можно добавить свои. Программ может быть до 20, активна одна.
- **Расписание** задаётся в программе одним из трёх способов:
  - *по очереди* — дни идут друг за другом без дат, следующий день — когда придёте;
  - *с интервалами* — после каждого дня своё число дней отдыха, например 1, 2, 1, 2. Пропущенная тренировка не теряется: она переносится на сегодня, и всё расписание сдвигается;
  - *по дням недели* — каждый день программы привязан к дням недели.
- **Какой день сегодня.** Кнопка «Другой день» позволяет выбрать сегодняшний день вручную; расписание продолжается от выбранного. Тренировка вне программы — «Свободная тренировка».
- **Тренировка.** При старте подходы заполняются по правилам прогрессии (ниже), а в первый раз — из программы. Рядом показан прошлый результат. После отмеченного подхода запускается таймер отдыха. Всё сохраняется само; тренировку можно продолжить с другого устройства.
- **Прогрессия** — подсказка под упражнением и подставленные значения в подходах; их можно поменять. Сравнение идёт с прошлыми тренировками того же дня программы, а если упражнение раньше было только в других днях — с последним выполнением:
  - *с весом:* если в прошлый раз все подходы дошли до верха диапазона повторов, вес растёт на шаг из программы, а без него — на 2,5 кг для верха тела и 5 кг для ног (на весах до 20 кг — на 1 и 2,5 кг), повторы возвращаются к низу диапазона. Иначе вес тот же, цель — +1 повтор в каждом подходе, но не выше верха диапазона;
  - *застой:* если две последние тренировки с этим весом были ниже диапазона хотя бы в одном подходе, предлагается снизить вес на 10 % (с округлением вниз до 0,5 кг) и начать с низа диапазона;
  - *с собственным весом:* +1 повтор в подходе; на верху диапазона — подсказка добавить отягощение или усложнить вариант. Если в упражнении записан дополнительный вес, оно прогрессирует как упражнение с весом;
  - *на время* (планка, кардио): когда все подходы выдержали цель, время растёт на 10 % (на 5 %, если подход длиннее 10 минут), с округлением вверх до 5 секунд. Растяжка и йога повторяют прошлую тренировку без подсказки.
  
  Подсказка запоминается при старте тренировки и не меняется, пока вы правите подходы.
- **Прогресс по упражнению** — кнопка со стрелкой в карточке упражнения тренировки и «Мой прогресс» в справочнике упражнений. Для упражнений с весом — график расчётного максимума на 1 повтор по формуле Эпли (вес × (1 + повторы / 30), только подходы до 12 повторов: при большем числе повторов формула сильно завышает), для собственного веса — лучший подход по повторам, для упражнений на время — лучшее время. Над графиком — текущее значение, рекорд и изменение за период, нажатие на график показывает тренировку, ниже — та же история списком с лучшим подходом и объёмом. Учитываются последние 100 тренировок с этим упражнением.
- **Завершение.** В конце указывается нагрузка от 1 до 10, по ней считается расход энергии сверх обычного:

  `ккал = (MET × (0,6 + 0,08 × нагрузка) − 1) × вес × часы`

  MET — средняя интенсивность упражнений по таблицам Compendium of Physical Activities, взвешенная по выполненным подходам; единица — расход в покое, он уже учтён в обычном обмене. Вес берётся из последнего замера, без него калории не считаются. Длительность учитывается не больше 6 часов.
- **Связь с распорядком.** Начало тренировки ставит статус «Спорт» с названием дня, завершение закрывает его, удаление тренировки удаляет и отметку.
- **Виджет «Следующая тренировка»** на панели показывает, что сегодня по программе, и начинает тренировку одной кнопкой. Если тренировка запланирована в планировщике, виджет показывает её время и начинает её из слота.
- **Тренировки в группе.** Участники группы видят в вашем профиле активную программу, ближайшую тренировку и историю, а также могут открыть любую тренировку для просмотра и из неё — график прогресса по упражнению (только чтение). Тренировка видна и в блоке «Спорт» на шкале дня. Менять программы и проводить тренировки можно только свои, а владелец и администраторы группы — ещё и за детей.

## Питание

Блок «Питание сегодня» на вкладке «Рутина» и полный экран «Дневник питания» (стрелка в блоке).

- **Приём пищи — это блок «Еда» на шкале дня.** Фиксированных «завтрак, обед, ужин, перекус» больше нет: приёмы пищи дня — это ваши блоки «Еда» в распорядке, в порядке времени. Название подбирается по времени начала блока: 4–9 — завтрак, 9–12 — второй завтрак, 12–16 — обед, 16–18 — полдник, 18–22 — ужин, 22–4 — ночной перекус. В каждой записи — название, количество, калории, белки, жиры и углеводы; у приёма пищи и всего дня — итоги. Стрелки и календарь переключают дни (вперёд — не дальше недели).
- **Куда записывается еда.** На экране «Добавить еду» сверху выбор приёма пищи: блоки «Еда» этого дня или «Новый приём пищи» с временем начала и длительностью (15, 30 минут или час). По умолчанию выбран блок, который идёт сейчас (например, после статуса «Еда» в шапке), иначе — новый приём с текущего времени. Новый блок появляется на шкале дня при первом добавлении; если он попал внутрь другого блока, например «Работы», тот продолжится после еды. Нажатие на запись открывает изменение количества, перенос в другой приём пищи и удаление.
- **«Как вчера»** в меню приёма пищи ищет вчерашний приём пищи в пределах ±2 часов от его времени и копирует записи ближайшего. Если вчера в это время приёма пищи не было, ничего не копируется.
- **Без приёма пищи.** Если блок «Еда» удалить или сменить ему тип, его записи остаются в дневнике в разделе «Без приёма пищи» — нажмите запись, чтобы перенести её в приём пищи. Туда же попали записи, сделанные до перехода на блоки.
- **Что можно добавить:**
  - *продукт из справочника* — поиск по названию или сканер штрихкода. Если штрихкода нет в справочнике, открывается карточка нового продукта с данными из Open Food Facts. В дневник попадают только позиции с типом «Еда» и заполненными калориями; если КБЖУ нет, приложение предложит открыть карточку;
  - *своё блюдо* — из списка блюд;
  - *быструю запись* — когда продукта нет в справочнике: калории и, если известны, белки, жиры и углеводы за всю порцию.
  Рядом с поиском — «Недавние»: продукты и блюда с последним использованным количеством.
- **Граммы, штуки и порции.** Количество вводится в граммах (для жидкостей — в миллилитрах). У продукта можно указать «Вес 1 шт., г» в карточке справочника — тогда его можно добавлять штуками. У блюда — порции, если задан вес порции или число порций. Пока вводите количество, внизу пересчитываются калории и БЖУ.
- **Блюда** — свои рецепты: ингредиенты из справочника (тип «Еда») с весом в граммах и обязательный **вес готового блюда**. По умолчанию он равен сумме ингредиентов, но при варке и жарке вес меняется: 200 г сухой гречки после варки — 600 г, 1000 г сырого мяса после жарки — 720 г. КБЖУ на 100 г и вес порции считаются от веса готового блюда: сумма КБЖУ ингредиентов делится на вес готового блюда. Порция задаётся весом («300 г») или числом порций («получилось 3 порции» — порция = вес готового блюда / 3). Ингредиенты без КБЖУ считаются нулевыми и отмечаются предупреждением. Блюдо можно показать участникам своих групп: они добавляют его в свой дневник, но не меняют рецепт. До 300 блюд, до 50 ингредиентов в блюде.
- **Записи не меняются задним числом.** При добавлении в дневник сервер сохраняет в записи название, КБЖУ на 100 г и вес порции на этот момент, а итог записи считает от них. Если позже изменить рецепт блюда или КБЖУ продукта, прошлые записи останутся как были; удаление блюда или продукта тоже не затрагивает дневник. Изменение количества в записи пересчитывается от сохранённых значений.
- **Норма на день** берётся из цели («Цель и норма» — кнопка в дневнике, строка нормы в сводке или карточка «Питание и норма» в профиле). Поддержание — основной обмен по формуле Миффлина — Сан Жеора (вес, рост, возраст, пол) × коэффициент активности из профиля (1,2 / 1,375 / 1,55 / 1,725 / 1,9). Вес берётся последний на этот день. Если в профиле не хватает веса, роста, пола или активности, вместо нормы показано, что заполнить. Калории завершённых тренировок за день показываются отдельно и в норму не добавляются.
- **Цели для взрослых (18+):** снижение веса, поддержание, набор массы. Темп — в кг в неделю, из расчёта 1 кг ≈ 7700 ккал: снижение 0,25–1 кг, набор 0,2–0,45 кг. Можно указать целевой вес — покажется, за сколько недель он будет достигнут.
  - *Предохранители.* Дефицит не больше 25 % от поддержания, и норма не опускается ниже безопасного минимума — большего из основного обмена и 1200 ккал для женщин / 1500 ккал для мужчин. Профицит для набора — от 200 до 500 ккал в день. Если выбранный темп упирается в предел, норма считается по безопасному значению, показывается предупреждение и фактический темп.
  - *БЖУ под цель.* Белок: на снижении 2 г на кг, на поддержании 1,6 г, на наборе 1,8 г, но не больше 35 % калорий. Жиры: 0,9 г на кг в пределах 25–30 % калорий и не меньше 0,8 г на кг. Углеводы — остаток.
  - *Ручная норма.* Переключатель «Задать норму вручную» — свои калории (800–6000) и БЖУ в граммах или процентах (сумма 100 %). Если норма ниже безопасного минимума или калории из БЖУ расходятся с заданными больше чем на 10 %, показывается предупреждение.
- **Дети (до 18 лет по дате рождения).** Взрослая формула не применяется: норма считается по детским формулам IOM (EER) по возрасту, полу, весу, росту и активности; до 3 лет — по возрасту в месяцах и весу. Тренировки за последние 7 дней повышают уровень активности (2–3 тренировки — на ступень, 4 и больше — на две). Режимы похудения и набора и ручная норма для детей недоступны. БЖУ: белок по возрасту (не меньше 15 % калорий с 4 лет), жиры 30–35 %, углеводы — остаток (около 50–55 %). Норму детского профиля видят его управляющие в профиле ребёнка.
- **Где видна норма.** В сводке дневника, в блоке «Питание сегодня» и в карточке блока «Еда» («N % дневной нормы»). Участники группы видят норму, дневник и съеденное за день в профиле человека, в блоке «Питание сегодня» (свайп по людям) и в его блоках «Еда», но изменить их не могут.
- Ограничения: до 100 записей в день, до 10 кг или 50 порций в одной записи, быстрая запись — до 10 000 ккал. Новый приём пищи можно создать не раньше чем за 31 день (как и любую отметку распорядка); в существующие приёмы пищи записи добавляются за последние 10 лет и на неделю вперёд.

## Интерфейс

- **Навигация.** Слева вверху аватар и имя: открывают профиль, там же настройки (тема, язык, распознавание чеков) и выход. Ниже закреплены вкладки «Группы», «Рутина», «Финансы»; они видны при прокрутке, переключаются нажатием или свайпом, по умолчанию открыта «Рутина». Свайп переключает не больше одной вкладки: на телефоне — при сдвиге на 20 % ширины экрана, на ноутбуке горизонтальным жестом двумя пальцами по тачпаду (или колесом с Shift). Страница следует за жестом без возврата между событиями тачпада, после сдвига на 120 точек (на узком окне — на 20 % ширины) открывается соседняя вкладка, а инерция того же жеста игнорируется; следующий свайп работает сразу, как только начат новый жест. Горизонтальная прокрутка внутри вкладки (строка фильтров, график «Доходы и расходы», таблица) вкладки не переключает. Каждая вкладка помнит прокрутку и фильтры, пока вы переходите между вкладками и открываете списки. Ссылка `/app?tab=finance` (или `groups`, `routine`) сразу открывает нужную вкладку.
- **Полные списки** (операции, чеки, кошельки, банки, группы, справочники) открываются поверх вкладок. Слева вверху закреплён крестик, он возвращает ровно на то место, откуда открыли список; рядом «+», если в списке можно создать запись; справа лупа открывает строку поиска.
- **Справочники** — круглая кнопка справа внизу на любом экране: раскрывает товары и услуги, упражнения, блюда, категории товаров, места, города и улицы. Пока открыта экранная клавиатура, кнопка скрыта, чтобы не перекрывать поля ввода; диалоги и списки в окнах прокручиваются и сжимаются над клавиатурой.
- **Темы:** «Как в системе», светлая, тёмная и фиолетовая (тёмно-фиолетовый фон). Все цвета берутся из палитры темы; цвета графиков подобраны отдельно для светлого и тёмного фона и проверены на различимость при нарушениях цветового зрения. Выбор сохраняется на устройстве.

## Распорядок дня

- Вкладка «Рутина»: «План на сегодня», «Задачи на сегодня», «Учёба», шкала суток каждой вашей группы, «Баланс калорий», «Питание сегодня», «Запасы» и «Тренировки» — следующая тренировка и 5 последних изменённых программ, «+» создаёт новую, стрелка открывает все тренировки.
- **Люди в блоках.** В «Питание сегодня», «Тренировки» и «План на сегодня» над содержимым строка с именем и точками: свайп влево-вправо или стрелки переключают человека. Первым идёте вы, затем взрослые участники ваших групп, затем дети. «+» есть только у своих данных и у детей, которыми вы управляете; у остальных — значок глаза и просмотр без правки. В «План на сегодня» показываются только вы и ваши дети: чужие планы не открываются.
- **Статус в шапке.** На аватаре — значок текущего статуса, под именем строка вида «Работа · с 9:15 ▾». Нажатие открывает выбор: кнопки статусов (работа, еда, дома, в дороге, отдых, спорт, сон, учёба, другое), «Начать раньше» — 15, 30 или 60 минут назад или своё время — и комментарий. Новый статус закрывает предыдущий, отметки одного человека не пересекаются. Блок с заданным концом, вставленный внутрь другого (например, обед посреди «Работы»), разрезает его: после вставки прежний блок продолжается с тем же статусом и комментарием.
- «Распорядок группы» — шкала для каждого участника: цветные блоки статусов с иконками, легенда, подсказка с временем и комментарием, линия «сейчас». Обновляется каждые 30 секунд. Как и у графика калорий, период листается стрелками и меняется кнопками от 1 до 31 дня; на длинном периоде шкала прокручивается по горизонтали, а полночь подписана датой. Любой блок открывается нажатием.
- **Новый блок с шкалы.** Нажатие на пустое место в своей строке (или в строке ребёнка, которым вы управляете) открывает «Новый блок»: тип, дата, время начала (подставляется место нажатия с шагом 15 минут), длительность от 15 минут до 4 часов и комментарий. Блок можно поставить не раньше чем за 31 день и с окончанием не позже чем через сутки.
- **Карточка блока** — тип, время, длительность и комментарий. Свой блок можно изменить: сменить тип в выпадающем списке «Вид события» (в нём выбран текущий тип), перенести на другой день (кнопка с датой: начало и конец сдвигаются вместе), сдвинуть начало и конец (конец раньше начала — это следующий день, «Без окончания» тянет блок до следующего), поправить комментарий или удалить. Сдвиг подрезает соседние блоки; если новое время целиком накрывает другой блок, сохранить не получится — сначала измените или удалите его. Что внутри:
  - *Спорт* — тренировка, начатая в это время: день программы, упражнения и выполненные подходы, кнопка «Открыть тренировку»;
  - *Еда* — это и есть приём пищи: что съедено, калории, Б/Ж/У и доля дневной нормы. «Добавить еду» открывает дневник с этим приёмом, «Как вчера» копирует вчерашний приём ±2 часа, «Привязать записи» переносит сюда записи этого дня. Если удалить блок или сменить тип, записи останутся в дневнике в разделе «Без приёма пищи»;
  - *Работа* — задачи на день блока: задачи дня и общие задачи. Галочка закрывает задачу, значок отчёта рядом с задачей записывает, что сделано; всё записанное здесь собирается в «Сделано за этот блок» и помечается в истории задачи «в блоке „Работа“». Отсюда же можно добавить задачу и перейти ко всем задачам;
  - *Учёба* — корневые темы учёбы с прогрессом и заметки, сделанные за время блока, с подписью, к какой теме они относятся. «Заметка» предлагает выбрать тему из всего дерева и ставит время внутри блока; «Вся учёба» открывает экран «Учёба».
- **Кто что видит.** Распорядок, тренировки в блоках «Спорт» и еду в блоках «Еда» видят все участники ваших групп, переключателей больше нет. Детали работы и учёбы видит только сам владелец; закрытое показывается фразой «Участник не открыл …».
- **Кто что меняет.** Свои блоки меняет только владелец. Блоки ребёнка — создатель его профиля, владелец и администраторы групп ребёнка; для них в карточке блока доступны правка, удаление и «Добавить еду», а на шкале суток имя ребёнка отмечено карандашом: нажатие открывает выбор статуса.

## Баланс калорий

Блок «Баланс калорий» на вкладке «Рутина» — накопительный график для всех участников ваших групп, по линии своего цвета на человека (те же цвета, что у точек выбора человека в блоках). Ваша линия толще.

- **Как считается.** Баланс не обнуляется в полночь: если вчерашний день закончился на +200 ккал, сегодня линия продолжается с +200. Отсчёт идёт от последней коррекции (см. ниже), а если коррекций не было — с нуля в полночь первого дня, когда у человека появилась запись в дневнике или тренировка. Еда поднимает линию скачком в момент начала её блока «Еда». Калории равномерно расходуются по норме поддержания (TDEE из раздела «Цель и норма»): за сутки линия опускается ровно на эту норму. Завершённая тренировка сжигает дополнительно свой расход сверх покоя, распределённый на время тренировки. Для текущего дня линия заканчивается на текущем моменте.
- **Коррекция.** Нажатие на график открывает окно «Калории на это время»: в поле уже стоит значение линии в этот момент, его можно заменить и нажать «ОК». Создаётся точка коррекции (ромбик на линии): в это время баланс становится равен введённому числу, дальше график продолжается от него. Если рядом с этим временем (±30 минут) уже есть коррекция, в окне есть «Удалить коррекцию». Если на графике несколько людей, в окне можно выбрать, кого поправить: себя или ребёнка, которым вы управляете. Корректировать чужие линии нельзя.
- **Период.** Под заголовком стрелки листают период, «Сегодня» возвращает к текущему дню, кнопки «1 день», «3 дня», «7 дней», «14 дней», «31 день» меняют длину. На длинных периодах график шире экрана и прокручивается по горизонтали, ось калорий остаётся на месте; полночь отмечена жирной линией с датой.
- **Легенда** под графиком: имя, текущий баланс (+ — профицит, − — дефицит), а за выбранный период — съедено, израсходовано и сколько из этого дали тренировки. Нажатие на человека скрывает или показывает его линию. Если для человека не хватает данных для нормы (рост, вес, дата рождения, пол), подписано «нет нормы — расход не учтён»: линия показывает только еду, тренировки и коррекции.
- Наведение мыши показывает значения всех видимых линий в выбранный момент. График обновляется сам после изменений в питании, тренировках и распорядке и раз в 5 минут.
- Отдельных разрешений не нужно: питание и тренировки участников группы открыты всем её участникам. API: `GET /api/energy/day?date=YYYY-MM-DD&days=7&tz=Europe/Kyiv` (до 31 дня), `POST /api/energy/marks` (`person_id`, `ts`, `kcal`), `DELETE /api/energy/marks/:id`.

## Запасы (холодильник и склады)

Блок «Запасы» на вкладке «Рутина» показывает, что лежит на складе по умолчанию (продукты, у которых срок истекает сегодня или завтра, подсвечены); нажатие на продукт открывает его карточку со списанием; стрелка открывает экран «Запасы», туда же ведёт значок коробки в дневнике питания.

- **Склады и склад по умолчанию.** У каждого есть личный запас, у каждой группы — общий запас группы. Склад по умолчанию выбирается в «Настройки» → «Запасы» (или кнопкой «Сделать складом по умолчанию» на экране «Запасы»): в него предлагается класть продукты из чеков и из него дневник питания списывает съеденное. Выпадающий список на экране «Запасы» переключает просматриваемый склад.
- **Поступление.** В чеке вместо переключателя — список «Продукты в запас»: «Не добавлять», «Личный запас» или запас одной из ваших групп; для нового чека подставляется склад по умолчанию из настроек. В запас попадают только позиции с типом «Еда»: количество × масса нетто из карточки товара (2 бутылки молока по 930 мл — 1 860 мл, 1,255 кг гречки — 1 255 г). Товары, услуги и прочее в запас не попадают. Стоимость партии — сумма позиции с учётом скидки на весь чек. Правка чека пересчитывает его партии; если поменять склад, нетронутые партии переезжают, а начатые остаются на старом складе. Остатки можно добавить и вручную: «Добавить» → продукт → количество в граммах, миллилитрах или штуках, необязательная стоимость, дата покупки и срок годности.
- **Масса упаковки.** Партия штучного продукта запоминает массу упаковки, поэтому остаток показывается и в граммах (миллилитрах), и в штуках: «40 г (0,1 шт)». Если масса нетто в карточке товара не указана, продукт хранится в штуках и подписан «масса упаковки не указана»: из него нельзя списать граммы. Тогда в карточке продукта в запасах есть «Указать массу упаковки», а дневник питания после записи «съел 250 г» сам предлагает ввести массу. После этого остаток пересчитывается в граммы, а уже записанные в дневник порции (сделанные после поступления партии) списываются задним числом. Если массу нетто в карточке товара изменить (например, 290 г → 300 г), партии с этой упаковкой пересчитываются: 1 шт становится 300 г, съеденное остаётся в граммах.
- **Сроки годности.** У партии можно указать «Годен до»: при ручном добавлении, у партии из чека (меню партии → «Срок годности») и у готового блюда при приготовлении. Есть быстрые варианты +1, +3, +7 и +30 дней и выбор даты в календаре; срок можно изменить или убрать в меню партии. У партии видно «Годен до …», а за день до срока и в последний день — «Истекает завтра» / «Истекает сегодня» (оранжевым), просроченная — красным. Дата считается в часовом поясе склада: для личного запаса — владельца, для запаса группы — владельца группы (пояс устройства синхронизируется автоматически).
- **Автосписание просрочки.** Фоновая задача сервера раз в минуту ищет партии, у которых срок прошёл (наступила полночь следующего дня), и переводит остаток в отходы с причиной «Истёк срок годности» — с массой и стоимостью остатка для отчёта отходов. Участники склада получают уведомление «Списано по сроку годности» (см. «Уведомления»). Повторный запуск ничего не списывает дважды; если остаток просроченной партии вернулся на склад (удалили запись дневника), он тоже уйдёт в отходы, но без повторного уведомления. Просроченную партию автосписание больше не трогает, пока её срок не изменят.
- **Списание дневником (FEFO).** Запись продукта в дневнике списывает его со склада по умолчанию по правилу «первым истекает — первым уходит»: сначала партии с ближайшим сроком годности, затем партии без срока — от самых старых по дате поступления. Просроченные партии не списываются. Правка количества пересчитывает списание, удаление записи возвращает продукт на склад. Если продукта не хватило, запись всё равно создаётся, склад обнуляется, а в дневнике видно «нет на складе: 300 г».
- **Приготовление блюд.** «Приготовить» (на экране «Запасы» или в карточке блюда) открывает рецепт: граммы ингредиентов можно поправить или умножить кнопками ×0,5…×2, а вес готового блюда — указать после взвешивания. Ингредиенты списываются со склада по тому же правилу FEFO, нехватка отмечается в партии, а на складе появляется готовая партия с фактическим весом и КБЖУ на 100 г именно этой готовки (с учётом уварки и ужарки) и её себестоимостью. В дневнике при выборе блюда предлагаются партии готовки (по умолчанию самая старая) или «По рецепту»; запись из партии берёт её КБЖУ и списывает граммы с неё. Пока из партии ничего не съели и не выбросили, готовку можно отменить — ингредиенты вернутся на склад.
- **Списание.** Нажатие на продукт в списке открывает его карточку: остаток, партии и кнопка «Списать»; то же делает значок «−» справа в строке. Списать можно в граммах (миллилитрах) или в штуках, если известна масса упаковки, — из всего продукта (сначала партии с ближайшим сроком) или из одной партии через её меню. Причина: «Использовано» (просто убрать из запаса), «Испортилось», «Истёк срок годности», «Не доели» или «Другое», плюс комментарий. Всё, кроме «Использовано», считается отходами: сохраняются масса и стоимость выброшенного, а «История» показывает все движения и итог отходов за период.
- **Кто что видит.** Личный запас видит только владелец. Запас группы видят и меняют все её участники: добавлять, готовить, списывать. В истории общего запаса у отходов, готовки и ручных добавлений подписан автор, а съеденное из дневника показывается без автора и без ссылки на запись дневника.
- Ограничения: до 20 000 партий на склад, количество в партии — до 1 000 000 г/мл/шт, дата ручной покупки — до 10 лет назад, срок годности — не раньше сегодняшнего дня при добавлении (при правке — не раньше даты поступления) и не дальше 10 лет, комментарий — до 500 символов.

## Задачи (работа)

Экран «Задачи» (стрелка в блоке «Задачи на сегодня» на вкладке «Рутина» или «Все задачи» в карточке блока «Работа»): стрелки и календарь переключают дни.

- **Два типа задач.**
  - *Задача дня* привязана к одному дню. Если её не выполнить, на завтра она не переносится и остаётся в своём дне невыполненной.
  - *Общая задача* появляется с указанного дня и висит каждый день, пока её не закроют; в списке видно, с какого дня она переносится («переносится с 15 окт., 3-й день»). В днях до закрытия она остаётся открытой, в день закрытия — выполненной.
- **Отметки.** Галочка закрывает задачу, при этом можно написать, что сделано. «Записать сделанное» добавляет отчёт без закрытия задачи — для длинных задач. «Вернуть в работу» снова открывает закрытую задачу с комментарием, почему.
- **История.** У каждой задачи журнал: когда создана, все правки в виде «было → стало» (название, подробности, тип, дата), отчёты о сделанном с датой и временем, закрытие, возврат в работу и уборка в архив. Журнал только пополняется: прошлые записи нельзя изменить или удалить — это проверяет сама база данных.
- **Архив вместо удаления.** «В архив» убирает задачу из списков, но её история и отчёты остаются.
- Задачи личные: их видит только автор, участникам групп в блоке «Работа» показываются только тип и время блока.
- Ограничения: название до 200 символов, подробности и отчёт — до 2000, дата задачи — в пределах года от сегодня, до 300 новых задач в сутки и до 1000 записей в журнале одной задачи.

## Учёба

Блок «Учёба» на вкладке «Рутина» показывает корневые темы с прогрессом; стрелка открывает экран «Учёба» с полным деревом, «+» добавляет новую тему.

- **Дерево тем.** Тема — курс, книга, предмет, глава, раздел — может содержать подтемы. Глубина ограничена переменной `STUDY_MAX_DEPTH` (по умолчанию 5 уровней). Сервер тем же движком, что и для категорий товаров, проверяет создание и перенос: тему нельзя перенести внутрь её собственной ветки (`409 TOPIC_CYCLE`), а новый уровень сверх лимита не создаётся (`409 TOPIC_TOO_DEEP`). Если лимит уменьшить, существующие глубокие ветки продолжают работать — их можно открывать, править и переименовывать; запрещено только создавать новые уровни сверх лимита и переносить ветку туда, где она его превысит. В окне переноса предлагаются только допустимые места. Тему с подтемами удалить нельзя, пока их не удалят или не перенесут; заметки темы удаляются вместе с ней.
- **Цель и прогресс.** У темы есть единица — проценты, страницы, задачи, уроки, главы или часы, — цель и сколько сделано. У темы без подтем прогресс — «сделано / цель» (больше 100 % не бывает), «Отметить прогресс» меняет значение и даёт быстрые +1, +5, +10. Прогресс темы с подтемами считается автоматически по подтемам:
  - если у всех подтем одна и та же единица (не проценты), их объём складывается: «160 из 400 стр.» → 40 %; перевыполнение одной подтемы не закрывает другие;
  - если единицы разные или это проценты — берётся среднее процентов подтем;
  - правило применяется рекурсивно на всю глубину, поэтому отметка в самом глубоком разделе сразу меняет прогресс всех родителей.
  Собственная цель темы с подтемами сохраняется и снова используется, если подтем не останется.
- **Заметки.** На любом уровне можно оставить заметку с датой, временем и текстом (до 5000 символов). Время по умолчанию — сейчас, его можно поменять: до 10 лет назад и не позже чем через сутки. У темы с подтемами переключатель «Эта тема / Вся ветка»: во втором режиме собираются заметки всех подтем, новые сверху, у каждой подпись источника — путь от текущей темы, например «Глава 2 › Раздел 2.1».
- **Блок «Учёба» в распорядке** показывает темы и заметки за время блока; заметку можно добавить прямо из карточки блока.
- Учёба личная: темы и заметки видит только автор, участникам групп в блоке «Учёба» показываются только тип и время.
- Ограничения: название до 200 символов, описание до 2000, заметка до 5000, цель и «сделано» — до 100 000, до 1000 тем и 20 000 заметок на человека; в режиме «Вся ветка» показываются 500 последних заметок.

## Планировщик

Блок «План на сегодня» на вкладке «Рутина» и полный экран «Планировщик» (стрелка в блоке) — личный план по неделям: стрелки листают недели, иконка календаря возвращает к текущей, «+» у дня создаёт событие на этот день. Текущее событие подсвечено.

- **Точное время или окно.** Событие бывает в конкретное время (стоматолог 14:00–15:00) или задачей в окне: «сходить в магазин за 40 минут с 12:00 до 18:00». Длительность — от 5 минут до 24 часов, окно не короче длительности.
- **Повтор:** каждый день, неделю (с выбором дней недели) или месяц, с шагом от 1 до 365 и необязательной датой окончания. Ежемесячное событие на 31-е число в коротких месяцах приходится на последний день. Изменения в редакторе применяются ко всей серии; отдельный день переносится или пропускается в меню события.
- **Часовой пояс.** Приложение определяет пояс устройства (IANA, например `Europe/Kyiv`) и подставляет его в новое событие; пояс можно сменить. Время хранится в поясе события, поэтому «каждый день в 9:00» остаётся в 9:00 и после перехода на летнее или зимнее время, а в поездке показывается в местном времени устройства. Если 9:00 в день перехода не существует, событие сдвигается на час вперёд; если повторяется дважды — берётся первое.
- **Отметки.** Галочка отмечает событие выполненным, в меню события — «Пропустить», «Перенести» (дата и время, не дальше года), «Изменить событие» и для событий с категорией — «Отметить статус» в распорядке.
- **Пересечения и перегрузка.** События с точным временем, которые накладываются друг на друга, помечаются «Пересекается: …» (выполненные тоже учитываются, пропущенные — нет). Окно помечается «Окно перегружено», если его длительность вместе с событиями точного времени внутри окна и вложенными в него другими окнами больше самого окна. Предупреждения показываются только у запланированных событий, у дня с проблемой — красный значок.
- **Тренировки.** Событие можно связать с программой: с конкретным днём или «Следующий по программе». Категория такого события — «Спорт». Кнопка «Начать тренировку» у сегодняшнего слота начинает тренировку нужного дня и связывает её со слотом; завершение тренировки отмечает слот выполненным, удаление тренировки возвращает его в план. Тренировка, начатая не из планировщика, закрывает сегодняшний слот той же программы. Виджет «Следующая тренировка» показывает время ближайшего слота («Сегодня в 19:00») и начинает тренировку из него.
- Ограничения: до 300 событий на пользователя, название до 100 символов, заметка до 500, просмотр — не больше 92 дней за запрос. События видны только их автору; события ребёнка видят и меняют те, кто им управляет.

## Уведомления

Колокольчик в шапке главного экрана открывает список уведомлений; число на нём — непрочитанные. Список работает всегда, даже если системные уведомления не разрешены: нажатие на уведомление отмечает его прочитанным и открывает нужный экран, «Отметить все прочитанными» — в шапке. Хранятся уведомления за последние 90 дней.

- **Типы** (каждый включается и выключается в «Настройки» → «Уведомления»):
  - **События планировщика** — за выбранное время до начала (по умолчанию 15 минут, от «в момент начала» до суток);
  - **Тренировки** — события, связанные с программой тренировок, со своим временем напоминания (по умолчанию за час);
  - **Истекает срок годности** — в 9:00 накануне последнего дня: «Истекает завтра» со списком продуктов склада; если партию с таким сроком добавили позже — сразу, а в последний день — «Истекает сегодня»;
  - **Списано по сроку** — когда фоновая задача перевела остатки просроченных партий в отходы.
  Напоминания о выполненных, пропущенных и уже начавшихся событиях не приходят. О запасе группы узнают все её участники, у кого включён этот тип.
- **Язык и часовой пояс.** Тексты уведомлений — на языке приложения, время — в часовом поясе устройства; приложение передаёт их серверу при входе и при смене языка.
- **Браузер (Web Push).** В «Настройки» → «Уведомления» кнопка «Включить» запрашивает разрешение браузера и подписывает это устройство; «Отключить» отписывает. Нужны ключи `VAPID_PUBLIC_KEY`/`VAPID_PRIVATE_KEY`/`VAPID_SUBJECT` на сервере: без них показывается «Push-уведомления не настроены на сервере», а уведомления остаются в списке. Сообщения шифруются для конкретного браузера (RFC 8291, `aes128gcm`) и подписываются VAPID (ES256), поэтому push-сервис браузера (Google, Mozilla, Apple, Microsoft) не видит текст. Сообщения обрабатывает service worker `push_sw.js`; нажатие на системное уведомление открывает приложение на нужном экране. У одного пользователя может быть до 10 устройств; подписки, которые push-сервис считает недействительными, удаляются автоматически.
- **Android.** Приложение показывает уведомления само, без сервисов Google: при входе, возвращении в приложение и после изменений в планировщике, складе и тренировках оно загружает расписание напоминаний на 48 часов вперёд и планирует их системными уведомлениями (Android может сдвинуть их на несколько минут для экономии батареи). Разрешение на уведомления (Android 13+) запрашивается кнопкой «Включить» в настройках; после перезагрузки телефона расписание восстанавливается.
- **Без дублей.** Каждое уведомление имеет ключ (событие и время начала, набор партий и дата), уникальный для пользователя, поэтому перезапуск сервера или несколько экземпляров бэкенда не создают повторов. Отправка push отмечается в базе; если сервер упал во время отправки, сообщение уйдёт повторно с тем же `Topic` и `tag`, и браузер заменит уведомление, а не покажет второе. Устаревшие (старше 6 часов) push не отправляются, при временных ошибках push-сервиса — до трёх попыток.
- **Выход из аккаунта** отписывает браузер (или отменяет запланированные уведомления на Android), чтобы следующий пользователь устройства не получал чужие уведомления.

## Роли в группе

| Роль | Права |
|---|---|
| Владелец | создатель группы; единственный, кто назначает и снимает администраторов, исключает администраторов, приглашает с ролью администратора, удаляет группу и передаёт владение. Владельца нельзя понизить или исключить; покинуть группу, где есть другие участники, он может только после передачи владения |
| Администратор | переименовывает группу, приглашает и исключает обычных участников, видит и отзывает приглашения |
| Участник | видит группу и её состав |
| Детский профиль | профиль без входа, которым управляют создатель и администраторы группы; см. «Детские профили» |

После передачи владения прежний владелец остаётся администратором.

## Вступление в группу

Участник добавляется только по одноразовому коду приглашения:

1. Владелец или администратор нажимает «Пригласить» и получает код вида `XXXX-XXXX-XXXX` (действует 7 дней, показывается один раз). Роль «администратор» в приглашении может выбрать только владелец.
2. Код передаётся человеку лично (мессенджер, устно).
3. Человек вводит код в разделе «Семейные группы → Вступить по коду».

Сервер хранит только хеш кода, ответы не позволяют узнать, зарегистрирован ли чей-то email.
